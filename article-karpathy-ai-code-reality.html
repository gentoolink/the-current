# When "Good Enough" Becomes Dangerous: What Karpathy's Code Confession Actually Means *And why the AI coding revolution has a hidden cost nobody's talking about* --- Andre Karpathy built an app called MenuGen. You photograph a restaurant menu, the AI OCRs the items, generates images of each dish, then re-renders the whole menu with pictures. It was a real application on Vercel with Stripe and Google authentication. It took effort. Then someone else did the same thing with a single prompt. Photo in, photo out, dishes rendered in place. No app. No code. No deployment. Karpathy's reaction on stage: "All of my MenuGen is spurious. That app should not exist." That moment captures something important about where software development is right now. Not the "AI is getting better" story — the real story, which is that the ground beneath developers is not just shifting, it is evaporating. --- ## What Karpathy Actually Said at Sequoia Karpathy — founding member of OpenAI, former head of AI at Tesla, and the person who coined the term "vibe coding" — spoke at Sequoia's AI Ascent conference in April 2026. The talk was billed as an update on vibe coding. What it actually delivered was something more honest. Here is what he said, in his own words, about the state of AI-generated code: > "Sometimes I get a little bit of a heart attack because it's not like super amazing code necessarily all the time. It's very bloaty, and there's a lot of copy-paste, and there's awkward abstractions that are brittle, and it works, but it's just really gross." And then, in the same talk, he described his workflow: he uses AI coding tools constantly, has largely stopped reviewing the output, and says he has never felt more behind as a programmer. Both things are true simultaneously. The code works. The code is gross. He stopped reviewing it anyway. --- ## The MenuGen Moment The MenuGen anecdote is more than a joke. It is a clean illustration of the difference between Software 2.0 and Software 3.0. - **Software 1.0**: Hand-written code. C, Python, Java. Every line intentional. - **Software 2.0**: Neural networks trained on data. The behavior emerges. - **Software 3.0**: Describe what you want in natural language. AI generates the code. You review the result. In Software 3.0, the bottleneck is not implementation. It is knowing what to build and whether what was built actually matches what you had in mind. Karpathy put it this way: > "You can outsource your thinking but you cannot outsource your understanding." The execution can be delegated. The comprehension cannot. --- ## Jagged Intelligence: Brilliant and Catastrophically Stupid in the Same Model Karpathy described a specific failure from his MenuGen project. His AI agent was trying to match Stripe customers to Google accounts. It used email addresses as the identifier. This is wrong — email addresses change, get reused, are not persistent user IDs. It is the kind of mistake a first-year engineer would not make. The same agent that wrote flawless authentication code had no common sense about identity systems. This is what Karpathy calls jagged intelligence. Opus 4.7 can refactor a 100,000-line codebase. It will also tell you to walk 50 meters to a car wash instead of driving there. The capability is not uniform. It is concentrated in areas where the labs invested heavily in RL training data, and absent everywhere else. His term for what happens when you do not account for this: the model makes wrong assumptions on your behalf and runs along with them without checking. It overcomplicates everything. The failure mode is not random. It is systematically wrong in the places training data is thin. --- ## Vibe Coding vs. Agentic Engineering Karpathy drew a distinction that is worth being clear about. **Vibe coding** raises the floor. Anyone can build something. The quality is variable, the reliability is low, but the barrier to entry is gone. **Agentic engineering** preserves the ceiling. Professionals can build production-quality systems this way, but it requires a completely different workflow — detailed specs, verification at every step, taste and judgment that stays human. The skill gap between the two is not incremental. Karpathy estimates someone using Claude Code with CLAUDE.md files, skills, subagents, plan mode, and worktree isolation versus someone typing prompts into a chat window is not a 10x difference. It is categorical. He published his own CLAUDE.md file as a set of four behavioral principles for coding agents. It hit 110,000 GitHub stars in weeks. The rules are simple. The fact that they went viral tells you something about how badly the defaults are broken. --- ## The "Slopacolypse" Prediction Karpathy has also predicted something he calls the "slopacolypse" — a wave of low-quality, AI-generated code that will hit production systems in 2026. He is not wrong to worry. A recent analysis found that 45% of AI-generated code contains security vulnerabilities. The tooling has gotten dramatically better at generating code. It has not gotten dramatically better at generating correct, secure, maintainable code. Those are different problems. There is also the atrophying problem. Karpathy acknowledged that as he relies more on AI to write code, he is starting to lose the ability to write it himself. The muscle that used to be load-bearing is becoming optional. Whether that comes back when needed is an open question. --- ## What This Means for the Rest of Us If Karpathy — who helped invent this technology, who has been inside the labs, who understands the architecture better than almost anyone — is having heart attacks when he opens pull requests, the average developer using ChatGPT to write a Python script should probably be paying closer attention than they are. The tools are real. The productivity gains are real. But the quality gap between "it runs" and "it's correct" is not closing on its own. It requires human judgment at every step — not to write the code, but to understand whether the code does what it is supposed to do and nothing it is not supposed to do. Karpathy's advice for anyone building with these tools: move beyond vibe coding into agentic engineering. Write detailed specs. Review the output not because you have to catch every bug, but because you have to stay in the loop. The moment you stop understanding what your agent is doing, you stop being able to direct it. The future of software is not a question of whether AI writes the code. It already does. The question is whether anyone is still paying attention to what it wrote. --- **Key takeaways:** - Karpathy built MenuGen as a real app; someone replicated it with one prompt.
